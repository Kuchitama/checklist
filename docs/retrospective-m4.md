## 3. 学び

### うまくいったこと

- **ドメイン → 画面 → 通しテストの順**（M3 と同じ）。ドメインの PR（#57）は指摘 0 で、画面の PR は指摘がそれぞれ 1〜2 件に収まった。
- **PR テンプレートの自己確認チェックボックス**（M3 のハーネス化 #1）を 5 件の PR で使った。「該当なし」と書く項目を 1 つずつ考えることで、#57 の時刻の扱い、#58 のルート param の再利用（同じ詳細画面の別 `id`）を PR を出す前に自分で確かめた。
- **3 つのブランチをローカルで積み、PR は 1 つずつ出す**（M2・M3 と同じ）。前の PR の指摘対応で先頭が動くたびに載せ替えた（6 回）。起点は前のブランチの履歴を書き換える前の SHA を使い、M3 の学び（`merge-base` の時機）どおりに進んだ。
- **計測を受け入れ基準に書く**（M3 と同じ）。#59・#60 の計測で検索ボックス・クリアボタン・チップ 20 個の 44px と `scrollWidth` 360 を確かめた。

### つまずいたこと

- **計測の入力が片寄っていた**（#59 の 0 件の文言、#60 の 1 文字のタグ）。横スクロールは「あ」100 文字で測り、CJK は折り返せるため英数字のはみ出しを見逃した。タップ領域は 30 文字のタグで測り、1 文字のタグの幅を見逃した。上限（長い・多い）だけでなく、下限（最短・1 文字）と文字種（英数字・CJK）の両方で測る。
- **shadcn の既定のフォーカスリングを疑わなかった**（#60）。`focus-visible:ring-ring/50` を他の部品と同じ書き方で付けたが、ライトの `--ring` は白で 2.59:1 で、50% 透明ではさらに低い。「新しい色は 3:1」の自己確認を、既存の書き方を写した色には当てはめていなかった。写した書き方でも、新しい要素に付く色は新しい色として測る。
- **フェイクタイマーと Dexie は相性が悪い**（#59）。`vi.useFakeTimers()` の下で `useLiveQuery` → Dexie → fake-indexeddb を動かすとテストがタイムアウトした。時間の境界（149ms / 150ms）はフックの単体テストでフェイクタイマーにより確かめ、画面のテストは実時間で挙動だけを確かめる分担にした。
- **衝突の解決で JSX を壊した**（#55 の載せ替え）。衝突ブロックだけを置き換えたつもりが、ブロックの外にあった行を重複させた。`rebase --continue` の前に `biome check` と `tsc --noEmit` を通していれば気づけた。
- **回帰テストを壊した後の戻しに `git checkout -- <ファイル>` を使った**（#55）。M3 の学び（CLAUDE.md 5 章 8）に反する。今回はステージしていない変更がほかになく被害はなかったが、規則どおり編集で戻すべきだった。
