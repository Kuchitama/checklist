## 3. 学び

### うまくいったこと

- **条件を満たす PR を自分でマージする進め方**（CLAUDE.md 5 章 7）は、人の介入なしに 5 件の PR を回せた。M1 で「人がマージを指示する」待ち時間が各 PR にあったのがなくなり、M2 は 1 日で終わった。判断を仰ぐ事項は「レビューしてほしい点」に書く代わりに、決めたこと（#39 のハンドルの `touch-action: none`）を共有として書いた。
- **自動レビューは PR 作成直後に API で依頼する**。リポジトリ設定の自動実行は数時間遅れることがあり（#35 で待った）、API で依頼すると数分で返る。以後の PR はすべて依頼した。
- **前の PR の CI・レビュー待ちの間に、次の Issue をローカルで進める**。PR は積まず（M1 の学び 7）、前の PR が squash マージされた後に `git rebase --onto origin/main <前の先頭> <ブランチ>` で `main` に載せ替えてから push した。#38 の指摘対応で前の PR が動いたときも、載せ替えの衝突は import 1 箇所だった。
- **計測で検証する**（M1 から継続）。#39 では、マウスは Playwright の `mouse`、タッチは CDP の `Input.dispatchTouchEvent`（150ms の長押しの前後）、キーボードは単体テストと、3 つの経路を別々に確かめた。jsdom は要素の位置をすべて 0 で返すため、dnd-kit を単体テストで動かすには `getBoundingClientRect` を並び順から計算した値に差し替える必要があった（`ListEdit.test.tsx`「並び替え」）。
- **設計書の不備を同じ PR で直す**（CLAUDE.md 1 章）は 5 件中 4 件で使った。#39 の 2 件（dnd-kit の読み上げ領域が `assertive` 固定、`--accent` が shadcn ではホバー背景）は、ライブラリの実際の挙動を実装して初めて分かるもので、設計時にすべて確認するのは高くつく。「実装が設計書の最終レビュー」（M1）は M2 でも成り立った。

### つまずいたこと

- **shadcn の `Input` が 32px のまま出荷しかけた**（#37）。M1 の学び 2（新しいタップ領域は 44px を測る）を入れていたのに繰り返した。計測スクリプトがボタンだけを測り、入力欄を「タップ領域」と読んでいなかった。ボタン・入力欄・リンク・チェックボックスなど、押せるものはすべて対象にする。`Button`（#23）と `Input`（#37）は既定のサイズを 44px に直したが、`Button` には `xs`（24px）、`sm`（28px）、`icon-lg`（36px）のように 44px 未満のサイズが残っている。部品の新旧ではなく、新しく設置・変更した操作要素を画面上で測る。
- **ブラウザの入力部品が `value` 以外に持つ状態を見落とした**（#38 の `validity.badInput`）。`<input type="date">` は不正・未完成の入力でも `value` が空になるため、空欄と同一視して期限なしで保存していた。IME の変換中（`isComposing`）は M1 で扱っていたのに、同じ種類の見落としだった。
- **ドメインが返しうるエラーを画面に全部つないでいなかった**（#38 の `unknown_id`、#35 の重複 id も同種）。`updateChecklist` が返す `["items", i, "id"]` の path に対応する入力欄がなく、無言で保存に失敗していた。ドメインのエラー `code` と path を列挙し、画面のどの欄に出すかを決めてから実装するべきだった。
- **一時的なエラー表示を、成功するすべての経路で消していなかった**（#37 の上限エラー）。また、**保存時の確定を検証より先にやっていた**（#37 の未確定タグ）。どちらも M1 の学び 4（イベントの順序を列挙する）の対象だが、「書き込みと購読の順序」と狭く読んでいた。状態遷移（出す → 消す）の経路と、確定・検証・保存の順序も列挙の対象にする。
- **環境の変化をイベントとして列挙していなかった**（#37 の幅の変更）。説明欄の高さは再描画のたびに測っていたが、端末の回転は再描画を起こさない。M1 の日付変更（#26）と同じく、時間・幅・可視性など、入力以外の変化を列挙する。
- **非テキストのコントラストを測っていなかった**（#39 の挿入位置の線）。M1 の学び 2 は「新しい色は文字と背景で 4.5:1」で、線や枠のような非テキストの表示（WCAG 2 の 1.4.11、3:1）を対象にしていなかった。設計書も `--accent` → `--ring` と、どちらも背景に近い色を指していた。
- **ライブラリが付ける ARIA の文字列が英語のままだった**（#39 の `aria-roledescription="sortable"`）。読み上げの文言は自前で日本語にしたが、ライブラリが既定で付ける属性までは見ていなかった。NFR-08（日本語のみ）の対象は、画面の文字だけでなく支援技術が読む文字列も含む。
- **ルートの param が変わっても同じコンポーネントが再利用される**（#36 の高）。`#/lists/A/edit` から `#/lists/B/edit` へ直接遷移すると、`useRef` に取った初期値が A のまま残った。param ごとに作り直すものには `key` を付ける。
