# チェックリスト管理ツール 要件定義書

- 作成日: 2026-10-18
- ステータス: ドラフト（レビュー待ち）
- 関連文書: [仕様書](./spec.md)

## 1. 背景と目的

繰り返し使う手順書、プロジェクトごとの ToDo、日々の習慣チェックなどを、ひとつのシンプルなチェックリストとして管理したい。
重要なのは「実行ログを蓄積すること」ではなく、**作ったチェックリストの項目そのものを手元に残し、必要なときに自分の他端末や知人へ渡せること**である。

## 2. ゴール

1. ブラウザだけで動き、ログイン不要で即座に使える。
2. チェックリストを作成・編集・実行（チェック）・リセットできる。
3. チェックリストをファイルとして書き出し、別の端末や知人の環境で読み込める。
4. スマートフォンでも PC でも快適に使え、オフラインでも開ける。

## 3. 利用者と利用場面

| 項目 | 内容 |
| --- | --- |
| 主な利用者 | 本人（個人利用）。1つのチェックリストを同時に操作するのは常に1人 |
| 共有相手 | 本人の別端末、知人 |
| 共有の形 | ファイルを書き出して渡す。相手は自分の環境に読み込んで、まっさらな状態から使い始める |
| 想定リスト | 手順書型（リリース手順、引っ越し準備など）、1回きりの ToDo 型、定期・習慣型（朝のルーティンなど） |

### 代表的なユースケース

- **US-1 手順書を作って繰り返し使う**: リリース手順をリスト化し、毎回チェックしながら進める。終わったらリセットして次回に備える。
- **US-2 ToDo を消し込む**: 旅行準備の持ち物リストを作り、揃えたものからチェックしていく。
- **US-3 習慣を確認する**: 毎朝のルーティンを並べ、終わったら手動でリセットして翌日に使う。
- **US-4 知人に手順を渡す**: 作った手順書をファイルに書き出し、チャットで送る。相手は読み込んでそのまま使える。
- **US-5 自分の別端末に移す**: スマホで作ったリストを書き出し、PC で読み込む。
- **US-6 似たリストを派生させる**: 既存のリストを複製して、一部を変えた別バージョンを作る。
- **US-7 増えたリストから目的のものを探す**: タグで絞り込む、またはキーワードで検索する。

## 4. 機能要件

### 4.1 チェックリストの管理

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-01 | チェックリストを新規作成できる（タイトル必須、説明は任意） | 必須 |
| FR-02 | チェックリストのタイトル・説明・タグを編集できる | 必須 |
| FR-03 | チェックリストを削除できる（確認ダイアログあり） | 必須 |
| FR-04 | チェックリストを複製できる（チェック状態は引き継がない） | 必須 |
| FR-05 | チェックリストにタグを複数付けられ、一覧でタグ絞り込みができる | 必須 |
| FR-06 | リスト名・項目名をキーワードで検索できる | 必須 |
| FR-07 | 一覧でリストごとの進捗（完了数 / 総数）が分かる | 必須 |

### 4.2 項目の管理

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-10 | 項目を追加・編集・削除できる（タイトル必須） | 必須 |
| FR-11 | 項目は1階層のフラットな並び（ネストなし） | 必須 |
| FR-12 | 項目をドラッグ＆ドロップで並び替えられる（タッチ操作対応） | 必須 |
| FR-13 | 項目に補足メモ（説明文、複数行）を付けられる | 必須 |
| FR-14 | 項目にリンク URL を付けられ、タップで別タブに開ける | 必須 |
| FR-15 | 項目に期限（日付）を付けられ、期限超過は強調表示される | 必須 |

### 4.3 実行（チェック）

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-20 | 項目をチェック／チェック解除できる | 必須 |
| FR-21 | チェックした日時を自動記録し、項目の近くに表示する | 必須 |
| FR-22 | リスト全体のチェックを一括で解除（リセット）できる。確認ダイアログあり | 必須 |
| FR-23 | 過去の実行履歴は保持しない（リセットで状態は消える） | 必須（方針） |
| FR-24 | 定期・習慣型も手動リセットで運用する。周期設定や自動リセットは行わない | 必須（方針） |

### 4.4 書き出し・読み込み（共有）

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-30 | チェックリストを1件ずつファイル（JSON）として書き出せる | 必須 |
| FR-31 | 書き出しにはテンプレート（タイトル・説明・タグ・項目定義）のみを含め、チェック状態と完了日時は含めない | 必須 |
| FR-32 | 書き出したファイルを読み込み、新しいチェックリストとして取り込める | 必須 |
| FR-33 | 読み込み時に内容をプレビューし、不正なファイルは理由を示して拒否する | 必須 |
| FR-34 | 読み込んだリストは既存リストと衝突せず、常に新規として追加される | 必須 |

### 4.5 データ保存

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-40 | データはブラウザ内（IndexedDB）に保存し、サーバーには送らない | 必須 |
| FR-41 | 詳細画面での操作（チェック／解除、リセット、複製、削除）と読み込みは即時に保存され、明示的な保存操作を必要としない。編集画面のみ「保存」で確定し、「キャンセル」で破棄できる | 必須 |
| FR-42 | 設定画面から全データを削除できる（確認ダイアログあり） | 推奨 |

## 5. 非機能要件

| ID | 要件 |
| --- | --- |
| NFR-01 | **静的ホスティング**: サーバーサイド処理なしで GitHub Pages に配置できる |
| NFR-02 | **オフライン動作**: PWA として動作し、初回ロード後は通信なしで起動・操作できる。ホーム画面に追加できる |
| NFR-03 | **レスポンシブ**: 幅 360px のスマートフォンから PC まで、横スクロールなしで操作できる。タップ領域は 44px 以上 |
| NFR-04 | **ダークモード**: OS 設定に追従し、設定画面で手動切替もできる |
| NFR-05 | **性能**: リスト 200 件・1 リスト 300 項目でも一覧・詳細が 1 秒以内に描画される |
| NFR-06 | **アクセシビリティ**: キーボードのみでチェック・編集ができる。フォーカス表示とラベルを適切に持つ |
| NFR-07 | **プライバシー**: 解析・トラッキングを入れない。外部通信は行わない |
| NFR-08 | **UI 言語**: 日本語のみ |
| NFR-09 | **技術**: TypeScript で統一。Vite + React |
| NFR-10 | **品質**: 単体テストと CI（lint・型検査・テスト・ビルド）を備える |

## 6. スコープ外（今回は作らない）

- アカウント、ログイン、サーバー保存、端末間の自動同期
- 複数人での同時編集、権限管理
- 実行履歴・達成率の蓄積、統計表示
- 周期設定による自動リセット、通知・リマインダー
- 項目のネスト（階層化）、セクション見出し
- 共有 URL、QR コード、Markdown 書き出し
- 全件まとめてのバックアップ書き出し（将来検討）
- 多言語対応

## 7. 前提・制約

- データはブラウザごとに独立する。ブラウザのサイトデータ削除で消えるため、大切なリストは書き出して保管する運用とする。
- 書き出しファイルの形式はバージョン番号を持ち、将来の互換性を保てるようにする。
- 「手順書型」「ToDo 型」「習慣型」は UI 上で区別せず、同一のデータモデルで扱う。用途の区別はタグで行う。

## 8. 受け入れ基準（リリース判定）

1. 第3章のユースケース US-1〜US-7 がすべて実機（iOS Safari / Android Chrome / PC Chrome）で完遂できる。
2. 第4章の「必須」要件がすべて動作し、対応する自動テストが通る。
3. 機内モードでアプリを再起動しても一覧と詳細が開ける。
4. GitHub Pages の URL を開くだけで利用を開始できる。
