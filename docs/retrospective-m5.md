## 3. 学び

### うまくいったこと

- **5 本のブランチを積み、PR は 1 本ずつ出す**。前の PR の指摘対応で先頭が動くたびに後続を載せ替えた（11 回）。起点を書き換える前に `merge-base` で控える運用（M3・M4 の学び）で、衝突は 0 回だった。
- **実物で計測する**（M3・M4 と同じ）。SW の更新は `dist/sw.js` を書き換えて実際に新しい SW を waiting にし、トースト → 「再読み込み」→ 新しい SW が制御するまでを headless Chromium で通した。オフラインは `context.setOffline(true)` で再読み込みし、フォーカスリングは Tab で移動して `box-shadow` を両テーマで読んだ。計測で分かったこと（`destructive` の 4.39:1、`focus()` では `:focus-visible` にならない）は PR と設計書に残した。
- **pre-push の `pnpm verify` が不安定なテストを捕まえた**（#70）。ファイル単体では 9 回通るのに、全件を並列に走らせると 5 回中 2 回失敗した。別 PR に切り出して先に直し、後続の PR を止めなかった。
- **依存の導入は環境の制約ごと記録した**。pnpm では `vite-plugin-pwa` の仮想モジュールが `workbox-window` を解決できない（直接依存に置く。仕様書 2 章）。Playwright のブラウザをダウンロードできない環境では `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` で既存の Chromium を使う（`docs/harness.md` 5 章）。

### つまずいたこと

- **shadcn の既定の色が基準に届かない箇所が、M4 の学び（写したクラスも測る）を入れた後も残った**。`destructive` ボタン（4.39:1 / 3.16:1）、`--input` の枠（1.26:1）、`ring-ring/50`、メニュー項目の `--accent`（1.07:1）。部品を画面に置くたびに 1 色ずつ見つけるより、部品の全状態（通常・ホバー・フォーカス・エラー・無効・選択済み）を一度に測るほうが早い。
- **ライブラリが自動で付ける ARIA の連携を上書きして切った**（#71）。本文の `id` を自前にしたら、Radix が `AlertDialogContent` に付ける `aria-describedby` が存在しない要素を指した。`toHaveAccessibleDescription` で描画結果を確かめていれば PR を出す前に気づけた。
- **フォーカスの「戻る先」を決めていなかった**（#71）。`AlertDialogTrigger` を使わずに開いたダイアログは、閉じても起点に戻らない。自己確認は「開くときの行き先」と「メニューを閉じた後」だけで、「ダイアログを閉じた後」を書いていなかった。
- **非同期の処理中の操作と、中断された後の再操作を列挙していなかった**（#71、#74）。削除の処理中にキャンセルできてしまう。再読み込みを `beforeunload` の確認で取り消すと、もう一度押しても skipWaiting の相手がおらず動かない。
- **IME の判定が `isComposing` だけだった**（#71）。Safari では変換確定の Enter が `isComposing: false` で届き、`keyCode` が 229 になる。
- **状態の組み合わせと特殊なモードを考えていなかった**（#75）。`aria-invalid` の半透明のリングがフォーカス中も残り `--primary` のリングを上書きした。`outline-none` は `forced-colors: active`（`box-shadow` が無効）でフォーカス位置を消す。
- **変異チェックで「通った」と誤認しかけた**（#71）。`sed` で壊したつもりの行が Biome の整形で折り返されていて置換が当たらず、テストが通ったように見えた。失敗の出力を見るまで変異が効いたとは言えない。
- **Copilot の要約だけの指摘を見落としかけた**（#71）。スレッドにならない「previously missed」の項目が 2 件あり、通知には出ない。レビュー本文を読んで PR コメントで対応を書いた。
- **Copilot のレビューには quota がある**。#76 の修正後の再依頼が「insufficient remaining quota」で実行されなかった。指摘にはすべて対応して解決済みにしてあり、追加の push はテストの判定を強めるだけで CI（E2E を含む）が緑だったので、CLAUDE.md 5 章 7 の条件を満たすと判断してマージした。
- **ブランチを切り替えると依存がずれる**。セッション開始のフックは現在のブランチの `package.json` で `pnpm install` するだけなので、依存の違うブランチ（`@playwright/test`、`vite-plugin-pwa`）へ切り替えたら手で `pnpm install --frozen-lockfile` が要る。
