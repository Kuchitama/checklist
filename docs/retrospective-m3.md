## 3. 学び

### うまくいったこと

- **ドメイン → 画面の順に Issue を切った**（#41 → #43、#42 → #44）。ドメインの PR は純粋関数と DB だけで、指摘が 0〜1 件に収まった。画面の PR はドメインを差し替えずに通しで書けた。
- **受け入れ基準に計測対象を明記した**（#43「ボトムシートとドロップダウンの両方で 44px」）。既存部品の見落とし（ドロップダウン 27px）が基準どおりの計測で見つかった。M2 の学び（部品の新旧ではなく画面上の要素を測る）が効いた。
- **3 つの Issue をローカルで積んで進め、PR は 1 つずつ出した**（M2 の学び 8）。前の PR の指摘対応で先頭が動いても、`git rebase --onto` で載せ替えられた。1 回だけ起点の SHA を誤り、衝突で気づいて `--abort` した。
- **ブラウザの挙動は実験で確かめた**（#48 のダウンロード）。`a` 要素の DOM への追加や `revokeObjectURL` の時機を 5 通り試し、どれでもダウンロードが起きることを確かめたうえで、headless Chromium では日本語のファイル名が `download` になる（ASCII なら正しい）ことを切り分けて PR に書いた。
- **回帰テストを 1 箇所壊して確かめる**を全 PR で続けた。#46 の `id` の混入、#47 の `version` の判定、#48 の `revokeObjectURL` とフォーカス復帰、#49 の 10 件の切り詰め、#50 の先頭 1 ファイル。

### つまずいたこと

- **規則はあったが適用が部分的だった**（#46 の年の桁）。CLAUDE.md 5 章 8 に「西暦 100 年未満」と書いてあり、0 時と年またぎはテストしたのに、100 年未満だけ落とした。規則を読んでも、項目ごとに「該当する／しない」を書き出さないと取りこぼす。
- **キーボード操作の後のフォーカスの行き先を決めていなかった**（#48 の操作メニュー、#49 の見えない input）。`ActionMenu` は項目を選ぶと常にフォーカス復帰を止めていた（確認ダイアログを開く項目しか想定していなかった）。`sr-only` の input はフォーカスできるが、見えている label にはリングが出ない。どちらも「フォーカスがどこへ行き、どう見えるか」を考えれば設計時に分かる。
- **`git checkout <file>` でステージしていない実装を消した**（#46）。回帰テストを壊すために編集した後、`git checkout` でファイルを戻したところ、インデックスには実装前の内容しかなく、実装ごと消えた。コミットはテストと型だけになり、pre-push の `pnpm verify` で止まった。壊す変更は編集で戻し、`git checkout` / `git restore` でファイルを戻さない。
- **計測の読み取りを誤りかけた**（#48 のドロップダウン 43.07px、#49 のフォーカスリングが透明）。どちらも開閉アニメーションや `transition-all` の途中を測っていた。描画が落ち着くまで待ってから測る。
